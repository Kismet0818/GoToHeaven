# GoToHeaven 面试讲解手册

> 用途：面试前 30 分钟过一遍；面试时按"项目速览 → 架构 → 我做的取舍 → 深挖一个点"的顺序讲。
> 所有行号基于当前工作区代码，路径相对仓库根 `GoToHeaven/`。

---

## 0. 一页速览（先背这一段）

**一句话定位**：一个 **runtime-only（逻辑零场景配置）的 2D 平台跳跃游戏框架**——启动场景里只有 1 个相机和 1 个 `GameCanvas` 实例，玩家、背景、音效全部由代码在运行时构建；关卡世界由 prefab 手摆、由 `LevelRepository` 自动发现；手感参数全部是 `public` 字段、可在 Inspector 里实时调。

**关键数字**（面试时可以报出来，证明你了解自己的项目规模）：

| 指标 | 数值 |
|---|---|
| 代码 | **37 个 C# 文件 / 5141 行**（两个程序集：`Assembly-CSharp` + `Assembly-CSharp-Editor`） |
| 关卡 | **4 关**（`level01`–`level04.prefab`，prefab 驱动、自动发现）⚠️ 见 7.1 的真实 Bug |
| 场景 | 1 个（`Boot.scene`）：Main Camera + 1 个 `GameCanvas` prefab 实例 |
| UI | 1 个 `GameCanvas` + 7 个界面 prefab（MainMenu/LevelSelect/Settings/HUD/Pause/Result/Fade） |
| 音频资源 | **0 个音频文件**——11 个音效 + 1 段 BGM 全部运行时合成 |
| 美术 | 72 张 png（像素素材）+ 19 个 Tile/Palette 资产；天空/山/云/星星/影子/白块等由 `ProceduralArt` 逐像素生成 |
| 玩法 | 跑跳、可变跳跃高度、二段跳、贴墙滑行 + 墙跳、空中冲刺、单向平台下穿、弹簧、锯片、移动平台、检查点、三星结算 |

**三个技术标签**（每个都能展开讲 5 分钟）：

1. **Runtime-only 架构**：不依赖场景里挂脚本、不依赖预制体里的 UI 引用，`GameBootstrap` 用 `[RuntimeInitializeOnLoadMethod]` 从任意场景启动游戏。
2. **数据驱动的手感**：物理自己积分（`gravityScale = 0`），土狼时间、输入缓冲、松键削减、墙跳锁全部是独立参数。
3. **程序化表现层**：没有音频资源、没有背景美术，天空渐变/星空/山体/云/BGM/音效都是代码生成——省掉资源管线，也把"能不能用代码表达"这件事讲清楚。

**面试时不要把"AI 生成"当成卖点也不要隐瞒**：这个项目用了代码生成与工具链（`Assets/Editor` 里有自检与冒烟测试），但**架构决策、参数调优、边界处理是你必须能解释的**。面试官问"这块为什么这么写"，答不上来就露馅。

## 1. 技术栈与工程事实

| 项 | 值 | 备注 |
|---|---|---|
| 引擎 | Unity **2022.3.62t7**（团结引擎 Tuanjie **1.8.5**，2022.3 分支） | `ProjectSettings/ProjectVersion.txt` |

| 分辨率 | 1920×1080（Web 960×600） | `ProjectSettings.asset` |
| 输入 | **旧版 Input Manager**（`activeInputHandler: 0`） | 键位硬编码在 `PlayerController` |
| 场景 | 只有 `Assets/Scenes/Boot.scene`，且在 Build Settings 里是唯一启用的 | 内容：Main Camera + 1 个 `GameCanvas` prefab 实例（名称覆盖在 L312） |
| 层（Layer） | 0 Default / 5 UI / 6 **Ground** / 7 **Player** / 8 **Hazard** / 9 **Collectible** / 10 **OneWay** | `TagManager.asset` |
| 关键包 | `com.unity.feature.2d 2.0.1`、`textmeshpro`、`ugui`、`modules.tilemap` | 还有本地包 `cn.tuanjie.ai.generators` |
| 代码规模 | 37 文件 / 5141 行；最大单文件 `PlayerController.cs` 496 行 | 见第 3 节 |

**两个只有读过工程才会说的细节**（加分项）：

- **两个程序集边界**：`Assets/Scripts`（运行时）与 `Assets/Editor`（编辑器）分开，所以 `GoToHeavenEditor` 能 `using UnityEditor` 而运行时代码不能——这是 Unity 的默认 asmdef 边界，也是"为什么冒烟测试要放在 Editor 目录"的答案。
- **3D 物理没用**：项目全是 2D 物理（`Rigidbody2D` / `BoxCast`），唯一的 3D 痕迹是 `manifest.json` 里的 `modules.terrain`（模板默认项，未使用）。

## 2. 架构：四层 + 一帧的时序

### 2.1 四层结构

```
┌─ 入口层 ────────────────────────────────────────────────┐
│ GameBootstrap  (RuntimeInitializeOnLoadMethod, 无场景依赖) │
│   └─ 创建常驻根 "GoToHeaven" + DontDestroyOnLoad + GameManager │
└──────────────────────────────────────────────────────────┘
                          ↓
┌─ 流程层 ────────────────────────────────────────────────┐
│ GameManager   状态机(GameState) + 关卡装载 + 计时/计分/存档    │
│ AudioManager  程序化合成音效与 BGM，三级音量                   │
│ UIManager     覆盖层界面路由 + Toast + Fade                  │
└──────────────────────────────────────────────────────────┘
                          ↓
┌─ 关卡层 ────────────────────────────────────────────────┐
│ LevelRepository  扫描 Resources 下的 prefab，按名字排序        │
│ LevelController  关卡总控：生成玩家、反向绑定实体、算边界、装配相机 │
│ LevelData/Definition  关卡元数据与（兜底用的）结构体定义        │
│ Coin / Checkpoint / Goal / Trampoline / SawTrap / Hazard …  │
└──────────────────────────────────────────────────────────┘
                          ↓
┌─ 表现层 ────────────────────────────────────────────────┐
│ PlayerAnimator / SpriteAnimator  帧动画（无 Animator 资产）   │
│ Backdrop / ProceduralArt / Fx   视差背景、程序化贴图、粒子      │
│ HudViews / MenuViews / UITheme  界面视图与主题                │
└──────────────────────────────────────────────────────────┘
```

**依赖方向是单向的**：关卡层知道表现层（`Coin` 会调 `Fx`），表现层只读关卡层的状态（`PlayerAnimator` 只读 `PlayerController` 的字段并订阅事件），`PlayerController` **完全不认识** `PlayerAnimator`。这是面试可以强调的"表现与逻辑分离"。

### 2.2 启动时序（从双击 Play 到能操作）

**第 0 步｜场景里有什么**：`Boot.scene` 只有两样东西——`Main Camera` 和 1 个 `GameCanvas` prefab 实例（里面有 7 个界面 prefab，挂的是 `UIManager`）。场景里**没有** `GameManager`、没有关卡、没有玩家。

**第 1 步｜引导（谁先跑）**：场景加载完成 → [`GameBootstrap.Initialize`](Assets/Scripts/GoToHeaven/Core/GameBootstrap.cs#L16)（`[RuntimeInitializeOnLoadMethod(AfterSceneLoad)]`）→ 先查 `GameManager.Instance`、再 `FindObjectOfType<GameManager>()` 双重判重 → `new GameObject("GoToHeaven")` → `DontDestroyOnLoad` → `AddComponent<GameManager>()`。
> 关键点：`AddComponent` 会**同步**触发 `Awake`，所以顺序是"场景加载完 → 建根节点 → GameManager.Awake → 下一帧 GameManager.Start"。

**第 2 步｜Awake 建服务（顺序不能乱）**：单例抢占（多余副本自毁）→ `DontDestroyOnLoad` → `targetFrameRate = 120 / vSync = 0` → `Art = new SpriteLibrary()`、`Levels = new LevelRepository()`、`Save = new SaveSystem()`（**构造即读档**）→ `SetupCamera()`（正交 `size 8`、位置 `(0, 3, -10)`、`SolidColor`）→ `Audio = new AudioManager(...)` → **UI**：优先 `FindObjectOfType<UIManager>()`（命中的就是场景里那个 GameCanvas 实例），找不到才 `Resources.Load("GoToHeaven/UI/GameCanvas")` 兜底实例化 → 建 `"Scene"` 根节点（后面所有关卡都挂它下面）→ `EnterMenu(initial: true)`。

**第 3 步｜进菜单**：`timeScale = 1` → `ClearScene` → `SetState(MainMenu)` → 相机清目标并复位 → `Backdrop.Create("menu")` → `HideHud` →（仅首启）`SetFade(1)` 全黑 → `ShowMainMenu` → 播菜单音乐。
> 为什么首启先全黑：下一帧 `Start` 里 `FadeIn(0.8f)` 淡入，用这 0.8 秒盖住首帧"程序化生成贴图/合成音频"的卡顿。

**第 4 步｜点 Play 进关**：主菜单 Play → `PlayFromMenu()` → `StartLevel(Save.IsUnlocked 的第一个未通关关)` → `LoadLevelRoutine` 协程：
```
上锁(transitioning) → FadeOut(0.18) → timeScale=1 → ClearScene
→ 取消音乐 duck → 重置 RunCoins/RunTime/Deaths
→ Instantiate(关卡 prefab) 挂到 Scene 根下
→ level.Initialize(data, this)   ← 生成玩家、绑定实体、算边界、装配相机与背景
→ SetState(Playing) → 收暂停层 / 隐藏全屏 / 开 HUD / 刷新 HUD
→ yield return null → FadeIn(0.3) → 解锁
```
> 为什么 `SetState(Playing)` 与刷 HUD 要放在 `Initialize` **之后**：HUD 一次就要拿到正确的 `TotalCoins`，否则会先显示 0 再跳变。

**第 5 步｜可操作**：`PlayerController.Update` 开始收输入，`FixedUpdate` 开始积分物理；`CameraFollow`/`Backdrop` 在 `LateUpdate` 跟上。

### 2.3 一帧内的分工（这是最容易被追问的"你懂不懂 Unity 执行顺序"）

| 阶段 | 谁在跑 | 干什么 |
|---|---|---|
| `Update` | `PlayerController` | **只采样输入**：跳跃按下/按住、冲刺、下方向、水平轴；写 `jumpBufferTimer` |
| `FixedUpdate` | `PlayerController` | **积分物理**：BoxCast 检测地面/墙/天花板 → 跳跃优先级判定 → 水平 `MoveTowards` → 重力/滑墙/限速 → 写回 `rb.velocity` |
| `Update` | `PlayerAnimator`、`Coin`、`SawTrap` | 纯表现：选帧、正弦浮动、旋转 |
| `LateUpdate` | `CameraFollow` | 平滑跟随 + 边界钳制 + 震屏 |
| `LateUpdate` | `Backdrop` | 视差分层（**必须在相机移动之后**，否则背景落后一帧抖动） |
| `FixedUpdate` | `MovingPlatform` | Kinematic `MovePosition` + 把位移补偿给玩家 |

> 一句话总结：**输入在 Update、物理在 FixedUpdate、相机与背景在 LateUpdate**。面试官听到这个分工，基本能确认你真的写过 2D 平台游戏。

## 4. 逐文件卡片

> 用法：面试官问"讲讲你这个模块"时，先报"职责 + 关键参数"，再挑一条"为什么这么写"。带 ⭐ 的是最值得主动展开的。

### 4.1 核心层（4 个文件）

#### ⭐⭐ `Core/GameManager.cs` — 454 行（第二重要的文件）
- **职责**：常驻总控。建服务、驱动状态机、编排关卡加载/转场/暂停/结算/存档、统一处理全局键盘。
- **服务持有**：`Art`(SpriteLibrary) / `Levels`(LevelRepository) / `Save`(SaveSystem) / `Audio`(AudioManager) / `UI`(UIManager) / `MainCamera` / `Level`(LevelController)。
- **状态机**（面试必答；`State` 只在 `SetState` 里赋值，全项目 6 处）：

| 迁移 | 触发 | 进入后做什么 |
|---|---|---|
| `Boot → MainMenu` | `Awake` 末尾 `EnterMenu(initial:true)` | `timeScale=1` → `ClearScene` → 清相机目标并复位 → `Backdrop.Create("menu")` → `HideHud` →（首启）`SetFade(1)` → `ShowMainMenu` → 菜单音乐 |
| `MainMenu → Playing` | Play 按钮 / Enter / 选关卡片 | `LoadLevelRoutine`：淡出 0.18s → 清场 → 重置 `RunCoins/RunTime/Deaths` → 实例化 + `Initialize` → `SetState(Playing)` → 刷 HUD → 淡入 0.3s |
| `Playing → Paused` | Esc / HUD 暂停按钮 | `timeScale=0` + 音乐 duck 0.35 + 弹暂停层（转场中会被 `transitioning` 挡住） |
| `Playing → Victory` | `Goal` → `CompleteLevel` | 算星 → **立即 `Save.RecordLevel` 落盘** → 等 0.9s（`WaitForSecondsRealtime`）→ 校验 `State + CurrentLevelIndex` 后弹结算 |
| `Playing → GameOver` | 生命耗尽 → 0.85s 死亡演出后 | `Deaths++` → 等 0.45s realtime → 弹失败界面（**不落盘**） |
| 任意 → MainMenu | 各界面 MENU 按钮 | 淡出 → `EnterMenu(initial:false)` → 淡入 0.35s |

- **星级规则**（`CalculateStars`，只有 4 行但经常被问）：初始 1 星；`RunTime <= parTime * 1.25f` → 2 星；`RunTime <= parTime && RunCoins >= data.CoinCount` → 3 星。**死亡次数不参与**；星级**不落盘**（存档只有 `bestTime/bestCoins/completed`）。
- **要点**：
  1. 转场全部走协程 + `transitioning` 锁，串行化，避免连点把状态改乱。
  2. "先存档、再弹胜利界面"——玩家直接杀进程也不丢成绩；等待用 `Realtime`，与 `timeScale` 解耦。
  3. `EnterMenu` **不重置**本局统计（只有 `LoadLevelRoutine` 才重置），所以菜单态读到的是上一局残值——这是设计而非 bug，但要能解释。
- **可坦白（很重要的三条）**：
  - UI 缺失时 `Awake` 只 `LogError`，但 `Update` 每帧 `UI.TickHud` 会持续 NRE；
  - `transitioning` 没有 `try/finally`，`Level.Initialize` 抛异常会**永久锁死**转场；
  - 转场失败路径只释放锁，画面停在黑场且 `State` 保持旧值。

#### `Core/GameBootstrap.cs` — 29 行
- **职责**：`[RuntimeInitializeOnLoadMethod(AfterSceneLoad)]` 在任意场景加载后建常驻根节点并挂 `GameManager`。
- **要点**：双重判重（`Instance` + `FindObjectOfType`）；先 `DontDestroyOnLoad` 再 `AddComponent`（保证首个场景卸载时根节点已属常驻区）。
- **面试可讲**："从任意场景按 Play 都能启动游戏"——这对 demo 和自动化测试（冒烟测试）特别有用。

#### `Core/GameState.cs` — 41 行
- **职责**：两个枚举。`GameState`（Boot/MainMenu/LevelSelect/Settings/Playing/Paused/GameOver/Victory）+ `Sfx`（11 个音效键）。
- **要点**：`LevelSelect` / `Settings` 是**死枚举**（选关与设置实际是覆盖层 UI，从未被 `SetState`）；状态没有 Enter/Exit 钩子，进入动作散落在 GameManager 各方法里——这是"状态机不够纯粹"的诚实评价。

#### `Core/GameLayers.cs` — 36 行
- **职责**：层号集中解析 + 两个语义明确的 Mask。
- **要点**：`Ground=6  Player=7  Hazard=8  Collectible=9  OneWay=10`；`GroundMask = Ground | OneWay`（可站立），`WallMask = Ground`（可贴墙）。**单向平台不算墙**——否则贴墙跳会挂在单向平台上，这是这类项目最经典的 bug。
- **可坦白**：`Hazard`/`Collectible` 没有对应 Mask，`Apply()` 全项目零调用。

### 4.2 数据层（5 个文件）

#### `Data/LevelData.cs` — 223 行
- **职责**：可 JSON 序列化的关卡数据结构 + 兜底关卡；当前主要作为"prefab 元数据 → 运行时 DTO"的载体。
- **要点**：`Vec2` 存在的原因是 **`JsonUtility` 不支持 `Vector2`**（注释里写着），并提供双向隐式转换让业务代码仍能当 `Vector2` 用；`Sanitize()` 补空数组、平台尺寸下限 0.5、`parTime` 下限 5、空 id 兜底；`CreateFallback()` 生成一个"至少能通"的最小关卡。
- **可坦白**：`platforms/coins/spikes/saws/movers/...` 这些数组在当前 prefab 驱动的流程里**已经不用了**，只有 `spawn`（兜底）、`killY`、`parTime`、`coinCount` 还在读；`goal` 字段是死数据。代码注释也承认这一点（注释已改成"保留用于兜底与 JSON 兼容"）。

#### `Data/LevelDefinition.cs` — 20 行
- **职责**：挂在关卡 prefab 根上的 7 个策划字段（id/displayName/subtitle/theme/parTime/killY/coinCount）。
- **要点**：纯数据容器，无 `OnValidate` 校验；缺这个组件的 prefab 会被 Repository 跳过并告警。

#### ⭐ `Data/LevelRepository.cs` — 72 行

### 4.5 关卡层（11 个文件）

#### ⭐ `Level/LevelController.cs` — 228 行
- **职责**：每个关卡 prefab 上的运行时总控。世界（Tilemap + 道具）在 prefab 里手摆，这个类只做：生成玩家 → 反向绑定实体 → 算相机边界 → 装配相机与背景 → 管存档点/金币/死亡/通关。
- **装配顺序**（被追问必答）：缓存引用 → 定出生点 → 金币编号 `Bind(this, i*0.7f)` → 绑定 Checkpoint/Goal/Trampoline/SawTrap → `BuildPlayer()` → 绑定 MovingPlatform（需要 Player 引用，所以必须最后）→ `BuildBounds()` → `SetupCamera()` → `Backdrop.Create()`。
- **要点**：
  1. 玩家是**代码搭出来的**，且**不挂在关卡下**（`new GameObject` 不设父）：SpriteRenderer（`sortingOrder 10`）→ SpriteAnimator → Rigidbody2D（`gravityScale 0 / Interpolate / Continuous`）→ BoxCollider2D（`0.72 × 1.72`，`offset (0, 0.88)`）→ PlayerController/PlayerHealth/PlayerAnimator → 子物体影子（`sortingOrder 9`）。
  2. 碰撞盒偏移的意义：原点≈脚底（`y ∈ [0.02, 1.74]`），所以"贴地判定、影子位置、平台承载"全用同一个坐标约定，不需要额外补偿；出生再抬 `+0.03` 避免卡进地面。
  3. `BuildBounds` 遍历所有 `Renderer` + `Collider2D` 取并集，**显式跳过 `ParticleSystemRenderer`**（粒子包围盒会飘），最后外扩 `左3 右3 下4 上6`。玩家是根物体、Backdrop 在之后创建，所以都不参与边界。
  4. 坠落判定 `y < Data.killY` 且 `!Depleted && !IsRespawning` 双重检查，避免结算/复活期间重复触发。
- **面试可讲**："关卡内容用编辑器摆，但玩家和相机边界是代码算的——这样同一个 prefab 能被不同分辨率和不同关卡复用。"

#### `Level/Backdrop.cs` — 223 行
- **职责**：纯代码生成的 **5 层视差背景** + 4 套主题配色（day/dusk/night/menu）。
- **要点**：
  1. 视差系数：天空 **1.0**（直接钉在相机上）、星星 0.92、远山 0.75、近山 0.58、云 0.30，纵向另有 0.9~0.95 与 -3/-4 的偏置。
  2. 全部用**负 sortingOrder**（-400 / -390 / -350 / -300 / -250）压在 Tilemap 与角色之下。
  3. 随机用 **`System.Random` + 固定种子**（星星 7、远山 11、近山 37、云 21），布局可复现且不污染全局随状态。
  4. 在 `LateUpdate` 里按相机位置**绝对赋值**（必须晚于相机移动，否则背景落后一帧抖动）；云在 ±34 处绕回做无限漂移。
- **面试可讲**："2D 里做纵深不需要 3D 深度，视差系数乘相机坐标就够了；固定种子保证每次进同一关，云的位置都一样，方便调试。"

#### ⭐ `Level/CameraFollow.cs` — 155 行
- **职责**：带边界钳制、朝向前瞻、震屏的平滑跟随相机。
- **要点**：
  1. 逐轴 `Mathf.SmoothDamp`：**x 0.16s、y 0.24s**——水平更硬跟手，垂直更软避免跳跃时镜头抖。
  2. 前瞻 `lookAhead = 1.1`：`Facing * 1.1`，转身瞬间目标点跳变 2.2 格，靠 SmoothDamp 吸收。
  3. 边界处理是**先判断"能否移动"再 clamp**：`Bounds.width > halfWidth*2` 才允许横向移动，否则锁中心——避免 `Clamp(min,max)` 在 min>max 时退化。
  4. 震屏用 `Time.unscaledDeltaTime`（暂停也能抖完）、线性衰减 `falloff = shakeTime/shakeDuration`、重叠触发取 `Mathf.Max`，结束把参数全部清零防残留。
  5. 单例 `Instance` + 静态 `Shake(strength, duration)`，让 `PlayerHealth` 这种没有相机引用的系统也能一行震屏。
- **可坦白**：`ComputeDesired(bool instant)` 的 `instant` 参数**函数体里没用到**；震屏偏移会回流进下一帧的平滑输入（应把基准位置与渲染偏移分开存）。

#### `Level/Checkpoint.cs` — 53 行

#### ⭐ `Level/MovingPlatform.cs` — 73 行
- **职责**：余弦往返平台，**带动玩家**。
- **要点**：
  1. 运动曲线 `0.5 - 0.5*cos(t)`：C¹ 连续、两端导数为 0，起停没有突变。
  2. `Bind` 强制 `bodyType = Kinematic` + `Interpolate`，移动用 `body.MovePosition`（不用 transform），保证物理引擎知道平台在动。
  3. **带动玩家不是父子关系、不靠摩擦**：每物理步算出 `delta`，判定玩家站在台面（脚点 vs `surface.bounds`，水平容差 0.12、垂直 `[-0.18, +0.28]`）后调 `player.CarryBy(delta)`——直接位移，平台的加速度不会传给玩家。

- **可坦白**：只取第一个 Collider，多段拼装的平台需要挂多个组件。

- **要点**：`Update` 里跑（纯表现，不需要物理步调），`Rotate(0,0,220*dt)` 自转；与 MovingPlatform 共用同一条余弦曲线，但一个 `FixedUpdate` 一个 `Update`——这是对"物理 vs 表现"步调差异的自觉取舍。

#### `Level/Trampoline.cs` — 65 行
- **职责**：弹簧，覆盖式起跳（不是叠加）。
- **要点**：三重门槛——`cooldown > 0` 返回、必须是玩家、**`SpeedY > 1f` 返回**（上升途中不二次触发，防连弹叠速）；`Bounce(power)` 直接覆盖 `velocity.y = 27` 并返还二段跳与空中冲刺，所以不同下落速度弹起高度一致；播完用协程 0.4s 回待机帧。

#### `Level/Platform.cs` — 15 行

### 4.6 玩家层（3 个文件）

#### ⭐⭐ `Player/PlayerController.cs` — 496 行（全项目最该讲的文件）
- **职责**：用脚本自维护的 `Vector2 velocity` **完全接管** 2D 平台手感；只通过 C# `event`（Jumped/DoubleJumped/WallJumped/Landed/Dashed）向表现层广播，不认识任何表现类。
- **参数表**（面试官很可能问"这些数字怎么来的"，至少要能解释量级）：

| 组 | 参数 | 默认值 |
|---|---|---|
| 移动 | `moveSpeed` / `acceleration` / `airAcceleration` / `friction` | 7.2 / 78 / 52 / 82 |
| 跳跃 | `gravity` / `fallMultiplier` / `maxFallSpeed` | -48 / 1.35 / 27 |
| 跳跃 | `jumpVelocity` / `doubleJumpVelocity` | 18.4 / 16.2 |
| 容错 | `coyoteTime` / `jumpBufferTime` | 0.11 / 0.12 |
| 墙 | `wallSlideSpeed` / `wallJumpPush` / `wallJumpUp` / `wallJumpLock` | -4.2 / 11.5 / 17 / 0.16 |
| 冲刺 | `dashSpeed` / `dashTime` / `dashCooldownTime` | 21 / 0.14 / 0.55 |

- **要点**：
  1. **不用引擎重力**：`gravityScale = 0`，每帧自己积分 `velocity.y += g*dt`。理由：只有这样才能在同一帧里叠加"上升 1g / 下落 1.35g""松键砍到 48%""滑墙夹到 -4.2""顶到天花板立刻清速"这些规则；交给引擎就要和 `gravityScale`/drag/材质打架。
  2. **无摩擦材质**（`friction=0, bounciness=0`）：水平速度完全由代码决定，贴墙不会被摩擦"粘住"，落墙不会二次弹跳。
  3. **检测全用 `Physics2D.BoxCast`**（地面/墙/天花板）而不是 `OnCollisionEnter` 接触点：判定有宽度，能容忍接缝；不依赖接触法线，斜坡不会误判成天花板。地面 BoxCast 只在 `velocity.y <= 0.25` 时算站地（防起跳当帧被"抓回地面"）。
  4. **跳跃优先级**：地面/土狼时间 > 墙跳 > 二段跳。墙跳排在二段跳前面是因为墙跳会**返还**二段跳，资源上不亏。
  5. **土狼时间**：站地每帧重置为 0.11s，离地后倒计时；**输入缓冲** 0.12s，落地前按下也算数，空中无可用跳跃时缓冲保留到落地帧。计时器只在 `ControlEnabled` 时递减（暂停不会攒过期输入）。
  6. **可变跳跃高度**：松键当帧 `velocity.y *= 0.48f`。
  7. **冲刺**：完全接管速度 `(dir*21, 0)`，每 0.035s 生成残影，结束时把水平速度降到 `moveSpeed*0.7`（避免"撞空气墙"）；`Continuous` 碰撞检测 + 0.14s 时长保证不穿墙。
  8. `Update` 采输入 / `FixedUpdate` 积分物理的分离，是"低帧率不漏键"的根本原因。
- **可坦白**：键位硬编码（旧 Input Manager，无法运行时重绑定）；残影每次 `new GameObject` 没有池；`WallSliding` 在冲刺分支不更新。

#### `Player/PlayerAnimator.cs` — 114 行
- **职责**：读 `PlayerController` 的状态字段选帧，订阅跳跃事件播一次性动作；**没有 Animator Controller 资产**。
- **要点**：状态优先级 = 一次性动作（受击 0.5s > 二段跳 0.55s > 墙跳 0.4s）> 空中（滑墙 9fps / 上升 1fps / 下落 1fps）> 地面（run 15fps / idle 10fps）；**上升与下落用 1fps 近乎定格**——像素角色高速移动时逐帧播放会抖，靠位移本身表达动作；翻面只看 `Facing` 符号。
- **可坦白**：锁定时长与帧率硬编码，美术帧数一变就要改代码。

#### `Player/PlayerHealth.cs` — 150 行
- **职责**：3 颗心、受击击退、无敌帧闪烁、回检查点复活、死亡上报。
- **要点**：
  1. **守卫顺序是刻意的**：`if (Depleted || IsRespawning || invulnerable) return;` **之后**才 `IsRespawning = true`——先上锁再 return 会永久卡在过渡态。
  2. **击退顺序不能反**：先 `Teleport(位置)`（内部清速度）**再** `AddVelocity`，反了击退会被抹掉。
  3. 受伤一律**回检查点**（0.38s 延迟），掉坑走快速通道 `FallIntoPit`（0.12s、不击退）——用不同延迟区分"被打飞"和"掉下去"。
  4. 无敌 1.2s，用 `Max` 叠加 + 重启闪烁协程；闪烁 `Mathf.Repeat(t, 0.16) < 0.09`（约 6Hz）；因为 `GetComponentsInChildren(true)`，影子会跟着闪（可坦白的小瑕疵）。
- **面试可讲**："状态锁要先判后锁""传送会清速度所以击退顺序不能反"——这两条都是踩过坑才知道的。

### 4.7 音频层（1 个文件）

#### ⭐ `Audio/AudioManager.cs` — 265 行
- **职责**：**零音频资源**——11 个音效 + 1 段 8.9s 的芯片音乐全部在内存里合成。普通 C# 类（不是 MonoBehaviour），由 GameManager `new` 出来。
- **要点**：
  1. 采样率 44100、单声道、`AudioClip.Create + SetData`；两条 `AudioSource`（music loop / sfx `PlayOneShot`），`spatialBlend = 0` 纯 2D。
  2. 四种合成器：`Sweep`（扫频）、`Arpeggio`（琶音，尾音 1.6 倍时长做交叠）、`Noise`（固定种子 5 + 单极点低通，用于冲刺风声）、`BuildMusic`（108 BPM、16 拍、Am→F→C→G、bass + 琶音 + 高八度点缀）。
  3. **扫频必须相位累加**（`phase += 2πf/SampleRate`）而不是 `sin(2πft)`——否则频率变化时相位跳变会爆音。这是最能体现"懂不懂音频"的一点。
  4. 音量三级（master/music/sfx）：SFX 在 `Play` 里逐次乘好并 `Clamp01`（所以 `sfxSource.volume` 固定 1，避免二次衰减）；音乐统一在 `ApplyVolumes`，暂停/过场 `SetMusicDucked(true)` 压到 0.35。
- **可坦白**：全部片段在构造函数里同步生成，启动有 CPU 峰值；参数硬编码无配置表；`Play` 查不到键会静默跳过（新增 `Sfx` 必须同步补合成）。

### 4.8 美术层（5 个文件）

#### `Art/ArtPaths.cs` — 41 行
- **职责**：所有 `Resources` 路径的**单一真相源**，全是 `const`（编译期折叠，零运行时开销）。
- **可坦白**：`GoalIdle` / `Spikes` / `Saw` 三个常量**零引用**；切图参数（单元格/PPU/轴心）没有集中在这里，散落在各调用点。

#### ⭐ `Art/SpriteLibrary.cs` — 118 行
- **职责**：运行时唯一的精灵工厂——自己切图，而不是用导入器的 Sprite Editor。
- **要点**：
  1. 整张 PNG 按 **Single Sprite** 导入，运行时 `Sprite.Create` 按横向长条切成帧：`count = texture.width / cellWidth`，**只取顶部一行**（Unity 纹理原点在左下）。
  2. 三条缓存字典 + 一个 `missing` 集合：命中缓存、**失败也缓存 `null`**、告警只打一次。
  3. 轴心即玩法对齐：`PlayerPivot = (0.5, 0.04)` 让脚底≈原点；`PropPivot = (0.5, 0)` 道具贴底；`CenterPivot` 给粒子。
  4. `TerrainTile(index)`：行优先、索引 0 在左上，`22×11 = 242` 块（由 352×176 推导），1 瓦片 = 1 世界单位。
- **面试可讲**："不吃导入器的切图结果，尺寸/PPU/轴心全由代码决定，运行时能换规格；代价是 Sprite 的生命周期要自己管（目前没有释放）。"

#### `Art/SpriteAnimator.cs` — 91 行
- **职责**：30 行状态机替代 Animator——吃 `Sprite[]` + fps，`Update` 累加推进。
- **要点**：`while (timer >= frameTime)` 消费累计时间（帧率无关、掉帧会补帧）；**同一序列引用相等且 loop 相同就直接返回**，所以调用方可以每帧无脑 `Play` 而不会把动画打回第一帧；`PlayOnce` 播完停末帧。
- **可坦白**：没有"播完回调"，导致每个使用方各写一份计时器（PlayerAnimator 三套 timer）。

#### `Art/Fx.cs` — 132 行
- **职责**：不依赖 ParticleSystem 的**自绘 Sprite 粒子**库：Dust / Confetti / Sparkle / Burst / OneShot。
- **要点**：每粒 = `SpriteRenderer + FxParticle`，`Update` 里手写积分（`velocity.y -= gravity*dt`、用水平速度驱动 `Rotate` 模拟纸片翻转）；`sortingOrder 30` 压在角色之上；`OneShot` 用 `frames.Length/fps + 0.1s` 定时销毁。
- **可坦白**：**没有对象池**，注释写着"尽量少分配"但实际逐粒 `new GameObject`；粒子不设父物体，会散落在场景根。

#### ⭐ `Art/ProceduralArt.cs` — 351 行
- **职责**：像素美术工厂——白块、渐变天空、圆角面板/按钮、爱心、星星、锁、圆、软阴影、云、山脊、暂停图标。
- **要点**：
  1. 统一 `NewTexture`：先算 `Color[]` 再一次性 `SetPixels`（避免逐像素 `SetPixel`）；全部 `RGBA32 / 无 mipmap / Point / Clamp`。
  2. **参数化缓存键**：`Panel/Button` 用颜色 RGBA 串做键，`Gradient/Hills` 把颜色、seed、高度都编进 key——同参复用、异参自动分裂。
  3. 天空渐变只要 **2px 宽**（横向同色，拉伸无缝）；山脊是**三层正弦叠加**（1/3/6 个周期 + 振幅 0.10/0.05/0.02），**不是 Perlin**，`System.Random(seed)` 只取初相位，所以同 seed 轮廓完全一致。
  4. 爱心用隐式方程 `(x²+y²-1)³ - x²y³ ≤ 0` 逐像素判定；五角星用射线法填充。
- **可坦白**：`Panel/Button/Heart/Star/Lock/PauseIcon` 六个 API **全工程 0 引用**（写了但没接进 UI）；静态缓存永不释放。

## 5. 三条主线深挖（面试官说"挑一个你最熟的讲讲"时用）

### 5.1 手感线：为什么不交给引擎

**一句话**：`Rigidbody2D` 只负责"碰撞与位移"，速度完全由代码积分。

`PlayerController` 在 `Awake` 里把 `gravityScale` 设成 0，然后在 `FixedUpdate` 里自己算：

```csharp
// 垂直：上升 1g、下落 1.35g，再按状态夹紧
float g = gravity * ((!Grounded && velocity.y < 0f) ? fallMultiplier : 1f);
velocity.y += g * dt;                       // gravity = -48
if (Grounded && velocity.y < -2f) velocity.y = -2f;  // 贴地吸附，防离地判定抖动
if (WallSliding) velocity.y = Mathf.Max(velocity.y, -4.2f);
if (velocity.y > 0f && CeilingBlocked()) velocity.y = 0f;
velocity.y = Mathf.Max(velocity.y, -maxFallSpeed);
```

**交给引擎会怎样**：`gravityScale` 是全局常量，做不到"下落比上升重 35%"；`drag` 与材质摩擦会和"贴墙不减速"打架；松键削减速度、贴墙限速这些规则没有一个现成的挂点。自己积分后，所有手感都变成"同一帧内的几条 if"。

**四个容错机制**（这是平台游戏的灵魂，值得逐条背）：

| 机制 | 值 | 解决什么 | 实现关键 |
|---|---|---|---|
| 土狼时间 | 0.11s | "明明刚离开平台，按跳却没反应" | 站地每帧重置计时器，`Grounded \|\| coyoteTimer > 0` 才算可跳 |
| 输入缓冲 | 0.12s | "落地前就按了跳，结果没跳" | `GetKeyDown` 写计时器，落地那帧消费；空中无跳跃时**不清零**，等落地 |
| 可变跳跃高度 | 松键 `×0.48` | 小跳/大跳可控 | 只在 `velocity.y > 0` 且非冲刺时削 |
| 站地阈值 | `velocity.y <= 0.25` | 起跳当帧被"抓回地面" | 上升中不判站地 |

**墙跳为什么排在二段跳前面**：墙跳会 `doubleJumpAvailable = true` / `airDashAvailable = true`（返还资源），所以"贴墙时按跳"先出墙跳不亏；反过来如果先出二段跳，玩家就少一次蹬墙机会。

**冲刺为什么不穿墙**：`Continuous` 碰撞检测 + 0.14s 时长（每物理步位移 `21×0.02 ≈ 0.42`，小于碰撞盒宽 0.72）+ 检测全用 BoxCast。

### 5.2 关卡线：prefab 摆世界，代码装配

```
Resources/GoToHeaven/Levels/*.prefab
        │  LevelRepository: LoadAll → 按名 CompareOrdinal 排序 → 必须有 LevelDefinition
        ▼
   LevelData（id/displayName/theme/parTime/killY/coinCount + Prefab 引用）
        │  GameManager.StartLevel → Instantiate → GetComponent<LevelController>()
        ▼
   LevelController.Initialize(data, game)
        ├─ 出生点：GetComponentInChildren<PlayerSpawn>(true) ?? data.spawn
        ├─ 金币：GetComponentsInChildren<Coin>(true) 编号 + Bind(this, i*0.7f)
        ├─ 绑定 Checkpoint / Goal / Trampoline / SawTrap
        ├─ BuildPlayer()            ← 代码搭玩家（含影子子物体）
        ├─ MovingPlatform.Bind(Player)   ← 必须在玩家之后
        ├─ BuildBounds()            ← Renderer + Collider2D 并集，外扩 3/4/3/6
        ├─ SetupCamera()            ← CameraFollow.Configure(8) + SetTarget(snap)
        └─ Backdrop.Create(cam, theme, transform)
```

**为什么是"反向绑定"而不是各自 `Find`**：所有实体由关卡一次性注入依赖，初始化顺序显式可见（谁依赖谁一眼看出），也给将来改对象池留了口子。**代价**：`Coin`/`Goal`/`Checkpoint` 里又用了全局 `GameManager.Instance.Art` 取美术，风格不统一（可坦白点）。

**事件回流**（实体 → 关卡的唯三入口）：

| 实体 | 调用 | 关卡做什么 |
|---|---|---|
| `Coin` | `level.CollectCoin(this)` | `CollectedCoins++`、`game.AddRunCoin()`、音效、Sparkle |
| `Checkpoint` | `level.ActivateCheckpoint(this)` | `SpawnPoint = flag.SpawnPoint` + `UI.Toast("CHECKPOINT")` |
| `Goal` | `level.CompleteLevel()` | 幂等锁 → 停控 → 胜利音 → `game.OnLevelCompleted()` |

**相机边界为什么容易出错**：`BuildBounds` 统计的是"调用那一刻"所有 Renderer/Collider 的包围盒。所以：① 粒子必须跳过（否则特效一飘边界就变）；② 玩家是根物体所以不计入（好事）；③ Backdrop 必须在它之后创建（否则背景贴图撑爆边界）；④ 远处误放一个装饰物，相机的可滚动范围就变了——这是我实际踩过的 bug。

### 5.3 表现线：没有资源也能出画面

**美术**：`ArtPaths`（路径常量）→ `SpriteLibrary`（运行时切图 + 三级缓存 + 轴心常量）→ `SpriteAnimator`（30 行帧播放器）。像素素材之外的一切——白块兜底、天空渐变、云、山、星星、影子——由 `ProceduralArt` 逐像素生成，并用"参数拼字符串做缓存键"保证同参只画一次。

**音频**：`AudioManager` 里没有任何 `AudioClip` 资产，11 个音效 + 1 段 BGM 用四种合成器在内存里算出来：

| 合成器 | 用途 | 关键实现 |
|---|---|---|
| `Sweep` | 跳跃、受伤、弹跳、点击 | 频率 `Lerp(start, end, t*t)` + **相位累加**（直接 `sin(2πft)` 会相位跳变爆音） |
| `Arpeggio` | 金币、检查点、胜利、失败 | 每音时长 ×1.6 做尾音交叠，样本 `+=` 叠加 |
| `Noise` | 冲刺风声 | `System.Random(5)` 固定种子 + 单极点低通 `Lerp(state, white, 0.22)` |
| `BuildMusic` | 8.9s 循环 BGM | 108 BPM、16 拍、Am→F→C→G、bass + 琶音 + 高八度点缀，最后统一 `Clamp(-1,1)` 防削波 |

**面试时的价值点**：这段代码证明你理解**采样率、相位、包络、多声部混音与削波**——比"我调用了 AudioSource.Play"强得多。

## 7. 我自查出的问题（面试时主动说，比被问出来强）

> 原则：每条都要能说清 **现象 → 定位方式 → 影响 → 怎么修**。主动暴露 2~3 条，比假装完美可信得多。

### 7.1 真实 Bug：`level04` 的 id 与 `level03` 重复（数据层）

- **现象**：现在有 4 个关卡 prefab，但 `level04.prefab` 的 `LevelDefinition.id` 仍是 `level03`，`displayName` 也还是 `Sky Ascent`。
- **影响**：`LevelRepository` 不校验 id 唯一性，会产出两个 `id = level03` 的关卡；`SaveSystem.GetRecord("level03")` 用 id 线性查找 → **两关的最佳时间/最佳金币互相覆盖**，通关记录合并。
- **怎么定位的**：读 `LevelRepository` 发现它以 `def.id` 为键 → 直接比对 4 个 prefab 的 `id` 字段 → 发现重复。也可以用菜单 `GoToHeaven ▸ Validate Project`（但它目前不校验 id，这也是它该补的一项）。
- **怎么修**：① 改 `level04` 的 `id`/`displayName`；② 在 `LevelRepository` 里加 id 唯一性检查，重复时 `LogError` 并跳过或加后缀；③ 把这条加进 `ValidateProject`。
- **面试价值**：这说明你会**顺着数据流去验证一致性**（id 是存档主键 → 主键唯一性 → 谁没校验）。

### 7.2 `LevelSelectView` 找的 `"Name"` 节点不存在

- 关卡卡片上的关卡名不会被代码赋值（`Find` 返回 null 后跳过），实际显示的是 prefab 里预置的文本。视觉上不崩，但换关卡数据不会更新名字。
- 修法：要么在 prefab 里补 `Name` 子节点，要么改成从 `Number`/`Stats` 同级找 TMP 组件。

### 7.3 每次切界面都会写一次存档

`UIManager.HideAllScreens()` 会调 `settings.Hide()`，而 `SettingsView.Hide()` 无条件 `Save.Save()` → 打开选关、暂停、结算……每次都写 `PlayerPrefs`。
- 修法：`Hide()` 里比对脏标记，或把落盘收敛到 `GameManager.ApplySettings()` 一个入口。

### 7.4 转场没有 `try/finally`

`LoadLevelRoutine` 里 `transitioning = true` 之后如果 `Instantiate`/`Initialize` 抛异常，锁永远不会释放，之后所有转场被挡，画面停在黑场。
- 修法：`try { ... } finally { transitioning = false; }`，或改成 `async` + `CancellationToken`。

### 7.5 UI 缺失时会持续 NRE

`Awake` 里 UI 加载失败只 `LogError`，但 `Update` 每帧无条件 `UI.TickHud(...)` → 每帧异常刷屏。
- 修法：`UI` 为空时 `enabled = false`，或 `TickHud` 内部判空。

### 7.6 几处小但真实的瑕疵

| 位置 | 问题 | 修法 |
|---|---|---|
| `UIAnimatedImage` | 索引先自增再赋值，首帧被跳过 | 改成先赋值再自增 |
| `HudViews.FormatTime` | `59.996` 显示成 `60.00` 不进位 | 先 `RoundToInt` 再拆分 |
| `CameraFollow.ComputeDesired` | `instant` 参数没被使用 | 删参数或真正实现"立即对齐" |
| `CameraFollow` | 震屏偏移回流进下一帧平滑输入 | 基准位置与渲染偏移分开存 |
| `Trampoline`/`Coin`/`Goal` 的 `Bind` | 用全局 `GameManager.Instance.Art` 而非 `owner` 传入 | 统一走注入 |
| `PlayerGhost` / `Fx` | 每粒 `new GameObject`，无对象池 | 预热池 + 复用 SpriteRenderer |
| `SpriteLibrary` | `Sprite.Create` 出来的资源无释放路径 | 提供 `Dispose`/`Resources.UnloadUnusedAssets` |

### 7.8 一个方法论教训（很适合讲）

我曾断言"`Fade.prefab` 没被任何地方引用"，因为 grep `m_Name: Fade` 在 `GameCanvas.prefab` 里 0 命中。**结论是错的**——Unity 的 **prefab 实例在 YAML 里不保存 `m_Name`**，名字以 `m_Modifications` 里的 `propertyPath: m_Name / value: Fade` 形式存在（第 409 行）。
- 教训：验证资源引用不能只按名字 grep，要么用编辑器 API（`AssetDatabase.GetDependencies`），要么解析 `m_SourcePrefab` + `PrefabInstance`。
- 这条特别适合回答"你怎么确认改代码没破坏资源引用"。

## 8. 高频问答 20 题（答案一句话起步，再展开）

1. **为什么不用 `Rigidbody2D` 重力？** → 需要在同一帧叠加多条规则（下落 1.35g、松键削减 48%、贴墙限速、顶天花板清速），引擎没有挂点；`gravityScale = 0` 后 `velocity` 完全可控。
2. **土狼时间和输入缓冲怎么实现，为什么是 0.11 / 0.12？** → 两个计时器：站地每帧重置 / 按下写 0.12s；都是"约 7 帧"的人类反应窗口，短到不会让人觉得"掉下去了还能跳"。
3. **为什么用 `BoxCast` 而不是 `OnCollisionEnter`？** → 判定有宽度能容忍接缝、不依赖接触法线（斜坡不误判）、可以在任意方向主动查询；代价是每帧固定开销。
4. **跳跃优先级为什么是"地面 > 墙 > 二段跳"？** → 墙跳会返还二段跳与空中冲刺，先出墙跳不亏资源；反过来会浪费玩家的蹬墙机会。
5. **冲刺怎么保证不穿墙？** → `Continuous` 检测 + 0.14s 时长（单步位移 0.42 < 碰撞盒 0.72）+ 落地/贴墙用 BoxCast。
6. **为什么单场景 + prefab 关卡，而不是每关一个 Scene？** → 换关只 `Destroy` 一个节点，无需 `LoadScene`，转场用协程淡入淡出即可；代价是关卡间无法有独立的场景级配置。
7. **玩家为什么是代码生成的？碰撞盒 offset 为什么是 0.88？** → 玩家是根物体，避免继承关卡变换；`offset (0, 0.88)` + `size (0.72, 1.72)` 让原点≈脚底，贴地判定、影子、平台承载共用一套坐标。
8. **相机边界怎么算的？** → `BuildBounds` 取所有 `Renderer` + `Collider2D` 并集、跳过粒子、外扩 3/4/3/6；玩家是根物体不计入，Backdrop 在之后创建也不计入。
9. **关卡比屏幕小的时候相机会怎样？** → 先判断"能否移动"（`Bounds.width > halfWidth*2`），不能就锁中心，避免 `Clamp(min, max)` 在 `min > max` 时退化。
10. **新增一关要做什么？** → 放一个 prefab 到 `Resources/GoToHeaven/Levels` + 根节点挂 `LevelDefinition`（填 id/名称/parTime）+ 摆 `PlayerSpawn`/`Goal`/`Coin`。不需要改代码——`LevelRepository` 自动发现并按名排序。
11. **金币总数信谁？删金币会影响三星吗？** → 信 prefab 里实际的 `Coin` 组件数（含未激活），元数据 `coinCount` 只在为 0 时兜底；所以删金币不用改元数据，三星阈值自动跟着变。
12. **存档存在哪？什么时候写？** → `PlayerPrefs` 的 `"GoToHeaven.Save.v1"`（Windows 落注册表 `HKCU\Software\DefaultCompany\GoToHeaven`）；通关**立即**写、改设置离开页面写、退出再兜一次；**死亡不写**。
13. **存档怎么兼容旧版本？** → 目前**没有**版本迁移：`version` 字段只声明没读，键名带 `.v1`；升版只能换键丢旧档。这是明确的待改进项。
14. **UI 为什么用 `transform.Find` 而不是 Inspector 拖引用？** → 因为 UI 是运行时实例化的，拖引用会丢；名字约定 + 启动期抛异常，装配错误能立刻发现；代价是节点改名只能靠运行时才发现（已有教训）。
15. **为什么不用 Animator？** → 像素游戏只需切帧，`Sprite[] + fps` 足够；省掉 Controller/Clip 资产与 Mecanim 开销；代价是没有混合、没有动画事件（所以三处自己写计时器）。
16. **没有音频资源，音效怎么来的？** → 代码合成：扫频/琶音/低通噪声/多声部 BGM；**扫频必须相位累加**，否则频率变化时相位跳变会爆音。
17. **性能上有什么隐患？** → 粒子与残影每次 `new GameObject`（无池）、`Sprite.Create` 出来的贴图无释放、`Resources` 全量常驻；量级小所以现在没爆，但这是明确的优化点。
18. **你怎么保证改了没坏？** → 三重：① 编辑器菜单 `Validate Project` 体检；② 批处理冒烟测试跑完整链路并以退出码回报；③ 改注释/重构时用"剥离注释后逐 token 比对 HEAD"的脚本证明零改动。
19. **这个项目最难的地方？** → 不是某个算法，而是**时序**：转场协程、暂停与 `timeScale`、玩家死亡演出与统计的交叉；其次是手感参数之间的耦合（改重力就得重调跳跃/墙跳/冲刺）。
20. **如果重做你会改什么？** → ① 抽 `IDamageable` 接口；② UI 用 ViewModel + 事件，而不是 `transform.Find` 字符串；③ 加对象池；④ 存档加版本迁移与 id 唯一性校验；⑤ 输入换成新 Input System 支持重绑定。

## 9. 两分钟口述脚本（照着念也不尬）

> "这是一个 2D 横版跳跃游戏，十几个关卡里现在有 4 关，37 个 C# 文件约 5 千行。它的特点是我把'场景配置'降到了最低：启动场景里只有一个相机和一个 UI 画布，游戏根节点、玩家、背景、音效全是运行时用代码构建的，所以从任意场景按 Play 都能跑起来，也方便我写批处理冒烟测试。
>
> 玩法上做了完整的平台游戏手感：土狼时间 0.11 秒、输入缓冲 0.12 秒、可变跳跃高度、二段跳、贴墙滑行与墙跳、空中冲刺。这些不是用 Rigidbody 的重力做的——我把 gravityScale 设成 0，自己在 FixedUpdate 里积分速度，因为只有这样我才能在同一帧里表达'下落比上升重 35%''松键把上升速度砍一半''贴墙限速'这些规则。
>
> 架构上分四层：入口层的 GameBootstrap 负责在任何场景启动；流程层的 GameManager 是状态机加关卡装载、计时计分、存档；关卡层是 prefab 手摆世界、LevelController 负责生成玩家、反向绑定实体、算相机边界；表现层是帧动画、五层视差背景和程序化音效。依赖是单向的——玩家控制器完全不认识动画和 UI，它只发 C# 事件。
